# 06 · 代码审查报告（第二轮：正确性 / 安全 / 加固）

> 对 v1 全量代码审查后发现的问题与修复，以及本轮新增能力（用户系统 / SQLite / 块类型）的验证结论。
> 全部修复均已有自动化测试或浏览器实测覆盖。

## 1. 正确性 Bug

### BUG-1（已修复）：结构调和不同步已有块文本 → 重连后显示陈旧内容
- **位置**：`client/src/editor.ts reconcileStructure`
- **现象**：断线重连对账（`onSnapshotResync`）与冲突重建（`rebuild`）只发 structure 事件；
  而 reconcileStructure 只增删/移动节点，**不更新已存在块的 textContent**。
  若离线期间他人改了某个已存在块，重连后本地 DOM 仍是旧文本；此时用户在该块输入，
  diff(模型新文本, DOM 旧文本) 会推导出一笔巨大的"删除+插入"，把对方的修改当成自己的删除回传服务器。
- **修复**：结构调和后对全部块执行 `syncBlockDom`（文本 + 勾选态 + 空块占位标记）。
- **教训**：DOM 与模型的事件驱动同步里，"结构事件不蕴含文本同步"是一个隐蔽的不变量缺口，
  任何"整体重建可见状态"的路径都必须强制 DOM 全量对账。

### BUG-2（已修复）：跨块焦点移动不释放旧块锁
- v1 遗留，本轮回归复测确认修复（focusout 按"目标块是否同一块"判断，跨块移动即释放）。

### BUG-3（已修复）：持久化挂在 Hub 消息路径上，绕过 Hub 的提交不落盘
- **现象**：`onSave` 由 Hub 的 tx 处理器调用；测试直连 `engine.submit` 的提交不会写库。
- **修复**：持久化改挂 `engine.onCommit`（引擎回调）——所有提交路径（WS、测试、未来其它入口）统一落盘。
  有测试（"SQLite 文档：每次提交即落盘"）专门覆盖。

## 2. 安全漏洞（Vulnerabilities）

### VULN-1（已修复）：身份伪造 —— hello 可携带任意 userId
- **危害**：任意客户端可用他人 userId 连接 → 冒名（presence/光标）+ **绕过块锁**
  （锁检查按 holderId 比较，同 userId 即豁免）+ 冒用同作者 CAS 豁免。
- **修复**：服务端签发随机会话 token（SQLite sessions 表）；hello 必须持有效 token 才能继承身份，
  否则一律新建访客。userId 永远由服务端生成，客户端不再上传。
- **测试**：auth.test（token 反查/登出失效）+ ws.test（token 继承/访客降级）。

### VULN-2（已修复）：跨站 WebSocket 劫持（CSWSH）
- **危害**：任意网页可在受害者浏览器中连 `ws://localhost:3000`（浏览器对 WS 不受同源策略约束），
  以受害者浏览器为跳板读写文档。
- **修复**：连接握手时校验 Origin：必须同源或 Vite 开发端口；无 Origin 的非浏览器客户端（测试/脚本）放行。
  越权连接以 1008 关闭。
- **测试**：ws.test"伪造 Origin 的 WebSocket 连接被拒绝"。

### VULN-3（已修复）：DoS 面 —— 无消息/操作规模限制
- **修复**：
  - WS `maxPayload = 512KB`（超限连接被 ws 库直接断开）；
  - 每连接令牌桶限流（2s 窗口 120 条，超限断开）；
  - 单 Tx `ops ≤ 200`、单条插入/删除文本 `≤ 100K` 字符（越界 nack INVALID + 错误提示）；
  - 认证路由 body 限制 16KB。
- **测试**：ws.test"超大事务被拒绝"。

### VULN-4（审查确认无问题）：注入类
- XSS：全部用户内容经 `textContent` 渲染（块文本、名牌、锁 chip、Toast、快照查看器），
  无 innerHTML 拼接用户数据；contenteditable 用 `plaintext-only`，粘贴走纯文本路径；
- 路径穿越：`/api/snapshots/:version` 经 `Number.isInteger` 白名单化，无法注入路径片段；
- SQL 注入：node:sqlite 全部参数化（`prepare().run(...)`）；
- 密码存储：scrypt(N=16384)+随机盐，登录比对用 `crypto.timingSafeEqual`（常数时间，防时序侧信道）；
  从不记录/返回密码或哈希。

## 3. 可靠性加固

| 项 | v1 | v2 |
|---|---|---|
| 持久化 | doc.json 防抖 200ms（硬崩丢窗口） | SQLite 每次提交即落盘（事务，重启零丢失，有重启一致性测试） |
| 身份 | 客户端自报 userId | 服务端会话 token（访客也统一走 token） |
| 用户名 | 会话内昵称 | 全局唯一（COLLATE NOCASE 唯一索引 + 预检查双保险），注册/改名明确报错 |
| 冲突提示 | 每 nack 一次 toast | 同文案 2.5s 去重 |
| 旧数据 | — | data/doc.json 首次启动自动迁移进 SQLite |

## 5. 残留风险（如实声明）

1. **HTTP 无 HTTPS**：登录接口在同源部署下安全；公网部署需上 TLS
   （token 在 WS 与 HTTP 中均以明文传输）。演示项目范围外，README 已注明。
2. **限流为单连接维度**：大规模分布式刷连接（海量短连接）未防护（需要 IP 级限流，见 README 优化方向）。
3. **`node:sqlite` 标记为 experimental**（Node 24）：API 已趋稳，本项目用量小（4 张表全参数化）；
   若转生产可平滑换 better-sqlite3，接口一一对应。
4. **撤销的既有限制不变**（docs/04）：线性撤销不感知他人同块修改。

## 6. v3 追加审查（多文档改造中发现并修复）

1. **Hub 房间化时丢失锁检查接线**：重写 Hub 后 `engine.setLockChecker` 的注入被遗漏，
   强制块锁永不拒绝——被"强制块锁"测试当场抓住。修复：DocManager 暴露按 docId 转发的
   lockChecker 注入点，Hub 构造时接线（引擎懒加载也能拿到正确的锁表作用域）。
2. **撤销快捷键只挂在编辑器容器上**：弹窗关闭/焦点丢失后 Ctrl+Z 失效
   （快照恢复后无法撤销的表象即由此而来）。修复：撤销/重做提升为页面级 document 监听
   （输入框内不拦截，交给原生）。
3. **临时测试库误迁移旧数据**：buildServer 使用自定义 dbPath 时也迁移了真实 doc.json，
   测试读到 v11 的旧文档。修复：迁移仅在默认库路径发生（`migrateLegacy: !dbPath`）。
4. 首页身份显示从 sessionStorage 名字改为服务器返回（`GET /api/docs` 携带 user），
   消除"改名后旧标签页显示旧名"的不一致。

## 7. v4 追加审查（移动端与体验修复）

1. **明暗切换闪烁**（用户报告）：两个根因——(a) 主题在入口脚本执行时才应用，
   暗色用户首帧看到白底（FOUC）；(b) body/顶栏/编辑器带 0.2s 颜色过渡且覆盖属性不一致，
   切换时各元素变色不同步，观感为"闪烁"。修复：主题应用移至 index.html `<head>` 内联脚本
   （首帧前生效）；删除全部颜色过渡，瞬时切换。实测：点击后 50ms 内即为终值。
2. **移动端布局**：桌面版固定定位的顶栏/文档栏在窄屏换行后会互相重叠 → 移动端转为
   静态流式布局；另修复 iOS 输入框聚焦缩放（<16px 触发）、触控目标过小（复选框 16→20px）、
   "/"菜单超出右缘（JS 钳制）、模态框横向挤压（纵向堆叠）、状态栏/横幅/Toast 溢出。
   390px 宽度实测：无横向溢出、菜单在视口内、布局正常。

## 8. v5 追加审查（七项新功能实现中发现并修复）

1. **搜索高亮失效**：CSS Custom Highlight API 的注册表是 `CSS.highlights`
   （`HighlightRegistry`，非 Map 实例），初版代码先从 `window.highlights` 取（undefined）、
   修正后又用 `instanceof Map` 判断（Registry 不通过）——两次都导致高亮静默降级。
   修复：按鸭子类型（有 set/has 即可用）判断。教训：对较新的 Web API 做 capability
   检测要用真实接口形状，而不是照搬 MDN 示例的类型名。
2. **测试装置问题（记录备查）**：CDP 环境下 `navigator.clipboard.readText()` 会因权限
   提示挂起整个求值通道（导出功能本体用 execCommand 兜底不受影响）；剪贴板验证改为
   单测覆盖纯函数 + UI 仅验证菜单结构。
