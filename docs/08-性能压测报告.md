# 08 · 性能压测报告

> 2026-09-22 · 单机实测（12 核 / 32G / Node v24.18.0 / Linux 5.15）。
> 复现：独立实例 `PORT=28999 E2E_DB=/tmp/x.db npm run start -w server`，另开 `node loadtest.mjs 28999`。
> 压测与生产实例同机（存在背景负载），数值偏保守；每场景前等服务端 CPU 静默，避免上一场景积压污染。

## 测试设计

单文档 520 块（接近大型笔记规模），五个维度拆开归因：

| 场景 | 变量 | 验证什么 |
|:---|:---|:---|
| A | 500 连接只在线 | 连接容量 / 内存 |
| B1 | 50 编辑者 @5 ops/s，无观众 | 纯仲裁 + 落盘开销 |
| B2 | 同 B1 + 200 观众 | 广播 fan-out 增量 |
| C | 50 编辑者满速突发 | 吞吐上限 |
| D | 20 人挤同一个块 | 块级 CAS 热点 |

## 结果

| 场景 | 结果 |
|:---|:---|
| **A. 500 连接同时在线** | ✅ 内存仅 ~165MB（≈0.3MB/连接，线性）；接入耗时 28s——每个新连接向全员广播 presence（O(N²) 风暴）+ 全量 init 快照，是接入速度的瓶颈而非内存 |
| **B1. 50 人各自块 @5 ops/s（无观众）** | 接近饱和：服务端 ~184 ops/s，p50=0.7s / p95=2.5s，**0 冲突 0 丢弃** |
| **B2. 同参数 + 200 观众** | 明显退化：p50=4.8s / p95=12s；广播使 CPU 涨 ~2.5×——围观人数直接吃编辑吞吐 |
| **C. 50 人满速突发** | 单进程上限 **60~190 tx/s**（与文档大小强相关） |
| **D. 20 人同块 @5 ops/s** | ~50% 操作被块级 CAS 拒绝（客户端变换重试）；拒绝路径本身极快（p50=4ms） |

## 结论：最大支持多少人

- **同时在线**：千人级无压力。500 连接仅 ~165MB；瓶颈是单进程 fd/内存而非协议。
- **同时编辑同一文档的舒适区：30~50 人**。50 人 @5 ops/s 已打满服务端容量（250 offered > ~180 tps），再多延迟进秒级；文档越大容量越低。
- **同段落并发是软上限**：20 人挤一块即 ~50% 拒绝重试；实际产品里块锁 UI（🔒 提示）会自然把同块编辑串行化，多数场景达不到这个压力。

## 瓶颈归因

每个 op 的服务端成本 = `structuredClone(整篇文档)`（engine 事务原子性）+ `整篇 JSON 落盘 SQLite`（每次提交即落盘的一致性取舍）+ `O(文档在线人数)` 广播。三者都在单线程事件循环上：

1. **吞吐 ∝ 1/文档块数**：千块文档的吞吐会降到几十 tx/s；
2. **吞吐 ∝ 1/在线人数**（有观众时）：广播扇出主导 CPU；
3. **单进程天花板**：所有文档共享一个事件循环，水平扩展需要 Redis 广播 + 文档分片（见 README 优化方向）。

这是"每提交即落盘、无外部依赖"架构的自觉取舍：换可靠性牺牲吞吐。

## 压测发现并已修复的 bug

**饱和积压时 sweeper 误杀活连接**（v15 修复）：`lastSeen` 在消息*被处理时*才更新，服务端积压 >15s 时（如 C 场景），仍在发送的编辑连接被判定超时批量 terminate（实测 C1 后 50 个编辑者全断，后续场景 0 ack）。

修复：两段式探活——空闲超过阈值先发协议层 ping（RFC 6455 客户端自动回 pong，pong 即续命），累计 **2×阈值无响应**才 terminate；超时/清扫间隔可注入便于测试。单元测试覆盖"空闲活连接存活"与"停止响应被剔除"两路径（`server/test/presence.test.ts`）。约束：清扫间隔须远小于空闲阈值，否则活连接的 pong 间隔可能超过 2×阈值。

**修复后全量复测**：C1/C2 场景 2500/2500 ops 全部 ACK（修复前 C1 丢 500 个、C2 全断 0 ack），编辑连接在 30s 饱和积压下全部存活；其余场景数值与首次一致（B1 tps≈194、B2 tps≈96、500 连接 RSS≈107MB），结论不变。

## 后续优化方向（按收益排序）

1. lastSeen 更新下沉到 socket 接收层（彻底消除处理滞后）
2. 广播合批（30ms 窗口内同文档 op 合并序列化）
3. 增量落盘（op log 追加 + 周期 checkpoint），摆脱整篇写放大
4. presence 广播去 O(N²)：加入风暴改为节流聚合
